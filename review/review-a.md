## Executive result

The brief's proposed post-fix score of about 8.25 is not supported at this HEAD. The most consequential issue is not missing polish: public props are still accepted and silently dropped, including form, validation, bounds, interaction, focus, and DOM/ARIA props. The new prop gate reports clean because it intentionally does not follow inherited `@lumo-ui/core` props. That scope is documented, but the surrounding claim that the class is closed is false.

The blind **7/10 overall** therefore stands. Accessibility/i18n/RTL remains the strongest axis, but even there first-byte ComboBox semantics, `Calendar`'s render-time clock read, and an ungraded EventCalendar grid prevent a 9. API/DX cannot be an 8 while `DateField` advertises form/bounds/DOM contracts it drops and `Button` silently resolves `onPress`/`onClick` by JSX spread order.

## Priority recommendations

1. Make inherited public props mechanically auditable. A TypeScript checker-based gate, or component-local resolved-prop manifests, should fail the five proved families above. Do not present `gate:props = 0` as whole-API coverage until then.
2. Close the silent API failures before adding breadth: DateField form/bounds/DOM forwarding, Button callback collision, Disclosure interaction props, CheckboxGroup read-only/required semantics, DialogHeading level.
3. Add contract tests for the exact missing variants: Button with both handlers, DialogHeading `level={4}`, DateField form submission and `aria-describedby`, typed date outside bounds, server ComboBox `aria-haspopup`, and EventCalendar grid gating.
4. Give `Calendar` an explicit/snapshot `today` input and add `grid → gridcell` to the HTML gate.
5. Refresh README/ROADMAP/brief from generated repository facts. Documentation claims should be tested like code claims, especially after an engine migration.
