# Lumo UI parity pass — 2026-08-13

## Scope and method

This is a current-source product-parity pass over the 94 `registry:ui` items, in registry order. Sources were opened on **2026-08-13**. The primary comparison is the live official [shadcn/ui component catalog](https://ui.shadcn.com/docs/components), individual shadcn Base UI pages/source shown there, the live [ReUI documentation](https://reui.io/docs), individual ReUI component/API pages, and ReUI's first-party [repository catalog](https://github.com/keenthemes/reui). Radix, Ark UI, and Mantine appear only where their official component materially reveals a category or capability absent from both primary comparators.

The prior `review-a.md`, `review-b.md`, and `review-c.md` were used only to route source checks. Their competitor facts were not treated as current evidence. That distinction mattered: the live shadcn catalog now includes Questionnaire and the chat family, while ReUI's live docs navigation includes File Upload and Icon Tile in addition to its older repository summary.

For ReUI, a `/docs/components/...` link means an installable ReUI-authored primitive with an API reference. A `/components/...` link means ReUI's official gallery of copyable shadcn compositions, not a separate primitive. Name matches were checked for function: notably, ReUI Frame and Icon Stack are not functional counterparts to Lumo's same-named components.

Materiality vocabulary:

- **Parity** — no meaningful shipped-capability gap for the component's stated job.
- **Optional breadth** — useful variants/examples, but not a defect in Lumo's narrower contract.
- **Material breadth** — not a correctness defect, but likely product-blocking for a named real-world use case.
- **Missing category** — no Lumo `registry:ui` component owns the capability; composition may still be possible.
- **Defect** — Lumo promises a behavior and does not deliver it. This comparison did not prove a new current defect; the differences below are parity/breadth findings unless explicitly stated otherwise.

## Ranked cross-library gaps

1. **Filters/query builder — genuinely missing `registry:ui` category.** ReUI's live [Filters API](https://reui.io/docs/components/base/filters) is a coherent component, not merely a demo: active filter state, field configuration, operators, text/select/multiselect/custom fields, validation, i18n, async server search, virtualized option rendering and Data Grid integration. Lumo has individual fields, FormState and a higher-level `filter-bar` block, but none of the 94 UI components owns a typed filter expression model. This is the clearest missing category for Lumo's dashboard audience.
2. **Advanced Data Grid/Table.** ReUI's [Data Grid](https://reui.io/docs/components/base/data-grid) materially exceeds Lumo in column/row pinning, DnD, grouping/tree rows, editing, footers, virtualization and infinite loading. Lumo's semantics and localization are stronger, but the production capability gap is large.
3. **Production scheduling: EventCalendar.** ReUI's [Event Calendar](https://reui.io/docs/components/base/event-calendar) provides five views, drag/create/move/resize, recurrence, time zones and external CRUD. Lumo is a strong Jalali-readable calendar, not yet a scheduling engine.
4. **Project planning: Gantt.** ReUI's [Gantt](https://reui.io/docs/components/base/gantt) adds day-to-year scales, split panes, zoom, drag/resize, progress, rollups and CRUD. This is a material product gap, though not a defect in Lumo's intentionally smaller Gantt.
5. **Upload lifecycle/state machine.** ReUI [File Upload](https://reui.io/docs/components/base/file-upload) and Ark [File Upload](https://ark-ui.com/docs/components/file-upload) own accepted/rejected files, limits, previews, transforms and richer capture/drop workflows. Lumo currently owns accessible acquisition and presentation, not upload state.
6. **Interactive questionnaire/wizard — genuinely missing behavior category.** Shadcn's new [Questionnaire](https://ui.shadcn.com/docs/components/base/questionnaire) owns items, choices, progress, previous/next/skip/submit, errors and actions. ReUI's [Stepper](https://reui.io/docs/components/base/stepper) owns per-step validation and form workflows. Lumo Steps is intentionally presentational progress navigation; FormState can compose a wizard, but no component owns the interaction/state contract.
7. **Async/virtual collection infrastructure.** Autocomplete, Combobox, Select, ListBox and Tree each have excellent localized/static behavior, but Ark/ReUI expose async, creatable, grouped and virtualized collection patterns more consistently. A shared collection seam would deepen several components at once.
8. **Overlay positioning/lifecycle infrastructure.** Popover, Tooltip, Dialog, Menu and HoverCard trail Radix/Ark in boundaries, portals, virtual anchors, outside interaction and focus lifecycle. This matters in editors, shadow roots and nested overlays more than in ordinary pages.
9. **Advanced date workflows.** Lumo leads on Jalali correctness and deterministic clocks, but ReUI/Ark/Mantine lead on multi-month, preset comparison, multiple selection, time coupling and staged Apply/Cancel workflows.
10. **Range/multi-value controls.** A multi-thumb Slider/RangeSlider is the clearest missing mode inside an existing category; it affects price/date filters and cannot be replaced by styling the single-value control.
11. **Responsive application shell/sidebar.** Shadcn Sidebar and Mantine AppShell integrate mobile overlay, breakpoints and persistence. Lumo deliberately splits these concerns, which is clean architecturally but leaves more work for every application shell.
12. **Example breadth, not primitive correctness.** ReUI's official catalog supplies dozens of copy-ready examples for Button, Button Group, Input Group, Select, Data Grid and common application layouts. Lumo's primitives are often more rigorous about localization/SSR, but ReUI materially reduces product assembly time.

## Categories that are not genuinely missing

- **Accordion:** Lumo Disclosure supplies the primitive behavior; coordinated multi-panel accordion state would be additive breadth, not an absence of disclosure capability.
- **Sheet:** Lumo Drawer is the same product category with logical placement.
- **Direction/locale provider:** Lumo Provider deliberately combines them rather than shipping two providers.
- **Field/Input/Label:** Lumo Form, TextField, TextArea, SearchField and InputGroup cover the category with stronger required-label wiring.
- **Typography:** native semantic text plus Lumo's component anatomy is an intentional styling strategy, not a missing interactive primitive.
- **ReUI Icon Stack:** the live [ReUI Icon Stack](https://reui.io/docs/components/base/icon-stack) is an isometric SVG illustration primitive; Lumo IconStack is an overlapping-child/overflow component. The name match is not functional parity and should not drive a rewrite.

## Bottom line

Across the 94 existing categories, Lumo's recurring advantage is not raw example count: it is Persian-first formatting and search, logical RTL geometry, deterministic server output, required caller-authored announced strings, authoritative semantic ownership and explicit first-byte IDREF/focus behavior. Shadcn and ReUI generally win on composition/example breadth; ReUI additionally wins on high-level dashboard engines. The parity pass found **two genuinely missing behavior categories** worth naming—**Filters/query builder** and **interactive Questionnaire/Wizard**—plus several large but explicitly additive depth gaps. It did **not** establish a new current Lumo correctness defect from competitor parity alone.
